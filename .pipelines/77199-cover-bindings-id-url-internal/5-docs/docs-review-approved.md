## Accuracy spot-check

- **Task 1 (compatibility table row).** Verified `core/cover`'s `id` declares `"role": "content"` in `packages/block-library/src/cover/block.json:18-21`. The new row `| core/cover | id, url |` at `docs/reference-guides/block-api/block-bindings.md:33` is positioned alphabetically after `core/button` (the existing convention is loosely-alphabetical-by-block-name); column alignment preserved versus the existing rows. Row matches the spec-mandated `id` + `url` set (Req 1, Req 2).

- **Task 2 (Cover-specific notes section).** Spot-checked four concrete claims:
  - "the editor surfaces the message `Internal media required for this binding.`" — exact literal match against `__( 'Internal media required for this binding.' )` at `packages/block-library/src/cover/edit/index.js:699`.
  - "the rendered front-end HTML omits the `<img>` element for that cover (the overlay still renders)" — verified `gutenberg_cover_bindings_strip_image` at `lib/compat/wordpress-7.1/block-bindings.php:293-307` removes only the `wp-block-cover__image-background` `<div>` or `<img>` element; the `wp-block-cover__background` overlay span and `wp-block-cover__inner-container` are untouched. Both `gutenberg_cover_bindings_render_block` paths (the unresolvable-config branch at lines 545-547 and the missing-resolved-value branches at 554-560) invoke `strip_image`, never erase the overlay.
  - "the iframe renders from the saved `url` attribute" on embed-video covers — verified the embed-video carve-out short-circuits BEFORE any binding-resolved URL substitution at `lib/compat/wordpress-7.1/block-bindings.php:534-536` and `237-239`; the existing `render_block_core_cover` embed-video path (in `packages/block-library/src/cover/index.php`) renders the iframe from the saved attribute unchanged.
  - "If a user has explicitly set `dimRatio` to a non-default value (for example `70`), that value is used as-is in both editor and front-end render" — verified server-side `gutenberg_cover_bindings_relax_dim_class` is only invoked when `100 === (int) ( $attrs['dimRatio'] ?? 100 )` at `lib/compat/wordpress-7.1/block-bindings.php:572`. Editor-side: `effectiveDimRatio = bindingActive && dimRatio === 100 && effectiveUrl ? 50 : dimRatio` in `packages/block-library/src/cover/edit/index.js` returns the stored value for any non-100 case.

- **Task 3 (Pattern Overrides on Cover example).** Spot-checked the `metadata.bindings.__default = { source: 'core/pattern-overrides' }` shape against `packages/patterns/src/components/pattern-overrides-controls.js:52-53`, which writes exactly that on toggle-on. Spot-checked the "keyed by `metadata.name`" claim against `packages/editor/src/bindings/pattern-overrides.js:14-23` where `getValues` reads `patternOverridesContent?.[ currentBlockAttributes?.metadata?.name ]?.[ attributeName ]`. The example's block comment metadata is correctly shaped and would deserialise into a working Cover block. Minor illustrative imprecision in the rendered HTML between the block delimiters (`has-background-dim-50` would not actually be emitted because `dimRatioToClass(50) === null` per `packages/block-library/src/cover/shared.js:32-36` — the saved markup for `dimRatio: 50` is `has-background-dim` only). This does not affect functional copy-paste usage because Gutenberg deserialises blocks from the comment-delimiter JSON, not the HTML body; flagging here for future cleanup but not blocking.
